# 澳门巴士运行观测仪表盘 —— 组长使用说明

## 一、你手上的文件

```
Macau_bus_crawler/
├─ group_export/
│  ├─ 导出数据.py          ← 把这个文件发给 5 位组员（每人一份）
│  └─ 操作说明.txt      ← 连同上面的 py 一起发给组员
└─ dashboard/
   ├─ submissions/          ← 【关键】组员交来的数据全部放这里
   ├─ build_dashboard.py    ← 汇总数据 + 计算指标（教学版，含阅读指南）
   └─ streamlit_app.py      ← Streamlit 界面，老师看代码时更容易理解
```

## 二、收齐数据后的操作（3 步）

1. 组员每人会交来一个 `提交_姓名.zip`，把它们**全部解压到
   `dashboard/submissions/` 文件夹里**（解压后每个 zip 会产生一个
   `提交_姓名/` 子文件夹，里面是 3 个 csv，保持原样即可，不用改名）。
   - 谁要是直接交了 `macau_bus.db`，也可以，把 db 文件丢进
     `submissions/` 即可，脚本同样能读（成员名取文件名，建议重命名为
     对方姓名，如 `提交_王五.db`）。

2. 在 `dashboard/` 文件夹地址栏输入 cmd 回车，先检查数据：

   ```
   python build_dashboard.py
   ```

   窗口会列出识别到的每位成员、轮次和线路。

3. 继续在 `dashboard/` 里执行：

   ```
   streamlit run streamlit_app.py
   ```

   浏览器会自动打开仪表盘。如果没有自动打开，就复制命令行里显示的
   `http://localhost:8501` 地址到浏览器。

> 数据有更新（补交、重跑）后，只需重复第 2、3 步。
> `submissions/` 为空时，脚本会临时回退读取项目根目录的
> `macau_bus.db` 生成预览版——这就是当前状态，方便先看效果。

## 三、仪表盘的四个模块

1. **小组总览**：6 人分工卡片（每人负责线路、轮次、车辆数、采集完整度）、
   每日抓取轮次、各线路车辆数、线路数据总表。
2. **车辆快照**：选线路、选日期、拖动快照时间，查看该轮巴士所在区段、
   车牌、车速和站点清单。
3. **拥堵热力图**：
   - 时段 × 区段：一眼看出几点、哪一段最堵（全部日期汇总）；
   - 日期 × 时段：车速 / 在运车辆两种日历视图；
   - 最拥堵区段 TOP 排名。
4. **多线路对比**：勾选线路，对比平均车速、观测车辆数、高峰在运、
   日均首站班次 4 个指标；并可看各指标从早 6 点到晚 23 点的变化曲线。

## 四、指标口径（写报告时请引用，避免被问住）

| 指标 | 计算口径 |
|---|---|
| 快照轮次 | 爬虫每 10 分钟抓取一次，一条线路一个方向记一轮 |
| 观测车辆数（配车规模） | 统计期内该线路出现过的**去重车牌**数，近似在册运营车辆规模 |
| 平均在运 / 轮 | 每轮快照观测到的车辆数的平均值，反映路上同时跑的车多不多 |
| 高峰在运 | 各轮在运车辆数的最大值 |
| 平均车速 | 网站对每辆车上报的路段速度（km/h）按范围求平均 |
| 首站班次 | 每小时在首站区段观测到的**不同车牌**数，按天数平均，近似发车班次 |
| 采集完整度 | 实际轮次 ÷ 按当天首末抓取时间跨度推算的理论轮次（10 分钟一轮） |

**数据局限（报告里建议主动说明）：**

- 数据是约 10 分钟一轮的**离散快照**，回放按轮逐帧显示，不是连续 GPS
  轨迹；段内位置缺失时圆点画在路段中间。
- 车速来自巴士报站网站的路段上报速度，非 GPS 实测；无速度上报时显示灰色。
- 数据库中**没有站点经纬度**，线路图为按站序排列的示意图，不代表真实地理
  走向与站间距。
- 晚间（约 23:30 后）无车属正常；爬虫停机、电脑睡眠会造成空窗，总览页的
  「采集完整度」即用于量化这一问题。
- 若两位组员爬了同一条线路，该线路数据会合并展示，车辆归属可能重复计入
  两人名下（按分工每人线路不同，正常不会发生）。

## 五、代码结构（教学版，方便向老师讲解）

全部代码刻意只用入门语法（普通 for 循环、if、字典、列表、字符串拼接），
没有难懂的高级写法；**所有统计都在 Python 里算好，Streamlit 只负责把数字画出来**。

**`build_dashboard.py`（组长运行，5 个部分，文件开头有同样的阅读指南）：**

1. 读数据：`read_db`（读自己的 .db）、`read_csv_group`（读组员交的 csv）、
   `find_csv_groups`（在 submissions 里找齐每个人的文件夹）、`collect_data`（汇总）；
2. 小工具：时间转换、求平均、线路编号、方向文字；
3. `calc_route`：对一条线路一个方向做全部统计（回放帧、热力图、对比指标）；
4. `calc_members` / `build_overview`：成员分工卡片和总览数字；
5. `build_data` / `main`：把统计结果组装成 Streamlit 可直接使用的数据。

**`streamlit_app.py`（界面代码，5 块）：**

1. 读取统计数据；2. 小组总览；3. 车辆快照；
4. 拥堵热力图；5. 多线路对比。

**`group_export/导出数据.py`（组员运行，3 步）：** 找到数据库 →
把 pages/stations/buses 三张表各导出一个 csv → 打包成 zip 并打印自查信息。

## 六、分析报告

仪表盘为「图表」部分。等 10 月 15–19 日 6 人数据全部到齐、重新生成
最终版仪表盘后，可基于完整数据撰写分析报告（建议结论方向）：

- 各组团/各时段拥堵规律（晚高峰是否最堵、堵点集中在哪些区段）；
- 线路间服务水平对比（班次密度、配车规模、商业/口岸长线与市区线差异）；
- 车队运营节奏（在运车辆的早晚高峰曲线、平峰运力冗余）；
- 数据采集质量评估（6 人完整度对比、空窗原因）。
